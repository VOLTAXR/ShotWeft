# ShotWeft Agent Storyboards

`agent storyboard` turns an original short-film screenplay into an editable ShotWeft project. It runs locally with deterministic rules. The same input and options produce the same scene order, shot order, relations, and durations. Project and item IDs, plus the update timestamp, are generated by the local project model at creation time.

## Input Format

Save the screenplay as UTF-8 plain text. A BOM is allowed; the maximum size is 1 MiB (1,048,576 bytes).

```text
1. 外景 旧码头 - 清晨
阿槐把铜纸鹤搁在缆桩上。潮水推来一张旧船票。
阿槐：原来你还留着这张票。
备注：先听到松动的缆绳。

INT. LIGHTHOUSE - NIGHT
老孟拧亮灯。阿槐把船票压在灯座下。
阿槐: 把灯留给下一班船吧。
```

The Chinese sample above is an intentional screenplay fixture and is not translated.

Scene headings start with `内景`, `外景`, `INT.`, or `EXT.` and may include numbering such as `1.` or `场景三`. Scene type is normalized to `内景` or `外景`. Time may follow a spaced hyphen, em dash, slash, or a recognized trailing time word, for example `内景：旧仓库 / 夜` or `场景三 外景 礁石滩 黄昏`. If time is omitted, it defaults to `日`.

Each line may contain action, dialogue, or a note. Ordinary narration goes into the scene `description`; `Character: line` and `Character：line` go into `dialogue`; notes, bracketed asides, and text before the first scene heading go into `notes`. If no scene heading exists, all text goes into one default scene. If there are more scenes than shots, later scene text is merged into the final retained scene and later headings are recorded in that scene's notes.

## Command

```text
shotweft agent storyboard <script.txt> <project.zip> --title <title> [--frame 16:9|9:16|2.39:1] [--shots 12] [--pdf <storyboard.pdf>]
```

- `--title` is required and must be 1–120 UTF-16 code units.
- `--frame` defaults to `16:9`.
- `--shots` defaults to 12 and accepts an integer from 1 to 50.
- `--pdf` exports a storyboard PDF using the existing layout and requires Playwright Chromium. Chinese display requires a system CJK font.

From the repository, run `npm run build:cli` first and use `node dist/cli/shotweft.js` as the command prefix.

## Complete Workflow

These commands are suitable for automation with stdin closed. Everything runs locally; no LLM or MCP is required. The Bash example uses `script.txt` in the current directory and new output paths. If you already have a web project ZIP, use it in place of `starter.zip`. `agent storyboard` creates a separate project.

```bash
cli() { shotweft "$@" </dev/null; }
first_id() { node -p 'JSON.parse(require("node:fs").readFileSync(0, "utf8"))[0].id'; }

cli project create starter.zip --title "候潮灯 项目草案"
cli project restore starter.zip imported.zip
cli agent storyboard script.txt project.zip --title "候潮灯" --shots 12
shot_id=$(cli shot list project.zip | first_id)
scene_id=$(cli scene list project.zip | first_id)
cli shot update project.zip "$shot_id" --title "潮水推来船票" --duration 4.5
cli scene update project.zip "$scene_id" --location "渡口外侧"
cli export json project.zip --output project.json
cli export zip project.zip --output delivery.zip
cli export pdf delivery.zip --output storyboard.pdf
cli agent verify delivery.zip
cli agent verify delivery.zip --pdf storyboard.pdf
cli project restore delivery.zip restored.zip
cli shot update restored.zip "$shot_id" --notes "保留缆绳声"
cli agent verify restored.zip
```

In the repository, replace `shotweft` inside the `cli` function with `node dist/cli/shotweft.js`. Install Playwright Chromium before `export pdf`. ZIP validation and validation of an existing PDF do not need a browser.

`export zip <zip> --output <new.zip>` preserves project data, media, and annotations. It refuses an existing target and returns `{"path":"<absolute-path>"}` on success. CLI restore preserves project, scene, shot, and asset IDs. The CLI reads manifest v1/v2/v3 and uses v3 when a DirectorPlan is embedded. In-place transactions preserve the existing manifest version unless the edit needs a newer supported version.

`agent verify <zip> [--pdf <storyboard.pdf>]` checks the ZIP manifest, scene/shot relations, entry allowlist, media sizes, and CRC. Results include the absolute ZIP `path`, the `project`, and a `summary`. With `--pdf`, it adds a `pdf` object containing the absolute `path`, byte size, page count, and title; `title` is `null` when absent. ZIP validation failure, or a missing, invalid, corrupt, or zero-page PDF, returns `1` and writes an error to stderr.

## Edit the Authoritative Project ZIP

For CLI workflows, the ZIP is the only authoritative project. `project.json` is its internal manifest; `project.direction` stores the DirectorPlan; originals and thumbnails live under `media/` and bundled photos under `photos/`. Standalone JSON is exchange data, not a second project store. No browser or IndexedDB is required for edits.

```bash
revision=$(shotweft project revision project.zip | node -p 'JSON.parse(require("node:fs").readFileSync(0,"utf8")).revision')
shotweft project apply project.zip operations.json --expected-revision "$revision" --dry-run
shotweft project apply project.zip operations.json --expected-revision "$revision"
```

`project revision` emits `{ "revision": "<sha256>" }` and hashes the full file as a stream; it does not parse the ZIP or use `project.updated`. Use `agent verify` to validate integrity. `project update` and all `scene`/`shot` in-place edit commands also accept `--expected-revision`; their results are unchanged. On a conflict, re-read the archive and review edits against its new revision before retrying. Do not automatically overwrite a newer project.

### Operations JSON schema

`operations.json` is a UTF-8 JSON array of 1–100 strict objects, up to 16 MiB. The [Zod schema](../src/cli/project-operations.ts) is authoritative. `op` selects a variant; extra fields (including in patches) are rejected. IDs are nonempty strings of up to 160 characters or references such as `{"ref":"pier"}` to an earlier add operation of the correct kind. `as` is optional and unique per batch: 1–64 characters, starting with a letter, then letters, digits, `_` or `-`.

| `op` | Fields besides `op` |
| --- | --- |
| `project.update` | Nonempty `patch`: `title` (1–120 characters, nonblank), `frame` (`16:9`, `9:16`, `2.39:1`), `archived` (boolean). |
| `scene.add` / `scene.update` | `patch`: `location`, `time`, `description`, `dialogue`, `notes` (strings) and `setting` (`内景` or `外景`). Add accepts optional `patch` and `as`; update requires `id` and a nonempty `patch`. |
| `shot.add` / `shot.update` | `patch`: `title`, `size`, `angle`, `movement`, `lens`, `notes` (strings), `duration` (seconds, `0 < duration <= 3600`), `sceneId` (scene ID/reference or `""` to detach). Add accepts optional `patch` and `as`; update requires `id` and a nonempty `patch`. |
| `scene.move` / `shot.move` | `id`, `position` (1-based integer). |
| `scene.delete` / `shot.delete` | `id`. Deleting a scene detaches its shots. |
| `director.plan.replace` | `plan`: a complete [DirectorPlan](../src/core/director/plan.ts), validated along with linked ZIP assets. |
| `director.plan.remove` | No other fields. If Director was active, select the existing video timeline or clear the selection. |
| `project.activeTimeline.set` | `timeline`: `video`, `director`, or `null` to clear. A named timeline must exist at this step. |

Scene and shot text fields allow up to 20,000 characters. Example:

```json
[
  {"op":"scene.add","as":"pier","patch":{"location":"Outer pier","setting":"外景"}},
  {"op":"shot.add","as":"wide","patch":{"sceneId":{"ref":"pier"},"title":"Wide shot","duration":4.5}},
  {"op":"shot.move","id":{"ref":"wide"},"position":1}
]
```

The success receipt has `previousRevision`, `revision`, `changed`, `committed`, `dryRun`, and ordered `operations` entries (`op`, and `id`/`as` where applicable). On dry-run, the ZIP is staged and verified but not replaced. The candidate digest and newly generated IDs describe that preview only; use `previousRevision` (not the candidate digest) for guarded apply, and use IDs returned by the committed apply. Malformed operation JSON/schema and malformed revision flags return `2`. Conflicts, missing references, invalid DirectorPlans and I/O/ZIP failures return `1`. The command does not import binary media or execute code from JSON.

### Transaction architecture

`updateProjectArchive(path, edit, { expectedRevision?, dryRun? })` in `src/cli/project-file.ts` accepts a synchronous or asynchronous edit that returns a complete new `ProjectArchive` (`project`, `items` with originals/thumbnails, `photos` and optional `manifest`). Keep unmodified items in the returned archive; the transaction carries forward manifest metadata. Return the input object unchanged for an explicit no-op. Extracted media is file-backed and valid only inside the edit; the receipt does not expose temporary blobs. Legacy `updateProject()` delegates to this API and still returns only the project.

Within the existing `.shotweft-lock`, the transaction hashes and reads the source, applies all edits, validates project references, stages one ZIP, reopens it for the same allowlist/size/CRC checks, hashes the staged ZIP, and rechecks the source revision before atomic rename. A failure before rename or a dry-run leaves the original bytes intact. The lock coordinates ShotWeft writers; the recheck detects external changes before commit but cannot replace a third party's own locking protocol. A stale lock is never removed automatically.

## Render a Video Timeline

Export a project ZIP after editing its timeline in the Video workspace. Supply local LGPL builds of FFmpeg and ffprobe with the `libopenh264` encoder and the required audio and video filters. Paths can come from `--ffmpeg` and `--ffprobe`, the `FFMPEG_PATH` and `FFPROBE_PATH` environment variables, or `PATH`.

Place standalone WAV, MP3, or M4A assets on Voice or Music in the browser. The CLI probes used audio with the `wav`, `mp3`, or `mov` demuxer and requires a decoder for its codec. The native AAC encoder produces stereo AAC-LC at 48 kHz. The renderer mixes overlapping clips, applies gain and mute, and fills gaps with silence. Audio-only timelines produce H.264/AAC-LC MP4 with a black picture. Source media and input ZIP bytes are preserved.

```bash
cli video verify timeline.zip
cli video render timeline.zip --output delivery.mp4
cli video verify timeline.zip --video delivery.mp4
```

Render returns the absolute MP4 `path`, the absolute `projectPath`, the `timeline` profile, and measured `video` properties. Archive-only verification returns `projectPath` and `timeline` and requires no media tools. Pass `--video` to also verify the MP4 with ffprobe. An existing render target returns exit code `1`.

## Output and Limits

Successful commands exit `0` and write one JSON line to stdout. For `agent storyboard`, `path` is the absolute ZIP path and `pdf` is the absolute PDF path when requested. Both Agent commands return the actual `project` stored in the ZIP, including scenes and shots. `summary` contains `scenes`, `shots`, and `duration` in seconds. Open the project from the web project home page with "Restore ZIP" to continue editing and export again.

Usage errors exit `2`. Invalid screenplays, existing targets, and write/render failures exit `1`. Errors are written as `{"error":"<message>"}` to stderr. Parent directories for ZIP and PDF targets must already exist; existing files are preserved.

Every retained scene gets at least one shot; remaining shots are allocated by action and dialogue length. A shot title comes from a text segment or the scene location. Duration is estimated from text length. Size, angle, movement, and lens rotate through a fixed sequence. Duration uses half-second steps and is capped at 8 seconds. Scene text and shot notes are truncated to the project format limits. Generated projects are text-first and use the editor's default backdrop; add images or video in the web app.

## Future LLM Boundary

The current command runs offline and deterministically, with no external AI or API call and no API key. A future LLM may be added as an explicitly enabled breakdown source that produces candidate scenes and shots only. Sending a screenplay to an external service requires explicit user choice and authorization. Candidates must still pass local project-format and relation validation before the existing ZIP and PDF write paths are used.
